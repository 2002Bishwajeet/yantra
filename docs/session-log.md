- **2026-07-30 (cont. 14)** — **Y-060 done: `yantra up <name> --agent claude`.** `yantra_core::agent` is deliberately shaped like `tmux::Tmux` — resolve a path once per connection, hold it, no cache key — with one departure that matters: **its candidate list includes `$HOME` and tmux's deliberately does not.** tmux's stated reason is that a `$HOME` install is on `PATH` by construction; for Claude Code that is simply false, because the installer writes to `~/.local/bin` and adds it to `PATH` by editing a shell rc file that a non-interactive ssh session never reads. `ssh <mac> 'command -v claude'` answers nothing while the binary sits right there — **I-34 for the third time, and the first where an existing assumption in our own code was the thing that was wrong.** Everything an agent needs is settled before tmux is touched, so a refusal leaves nothing half-open; that ordering is what makes the **`auth status` gate** worth having, and it was verified end to end against the real MacBook: `up --agent claude` refuses and names the keychain, while the same `up` without the flag still opens a session normally. **I-23 turned out to need no code, and that is a consequence of ADR-0011 rather than an oversight** — the trust dialog swallows *automated* keystrokes, and Yantra sends none; the hazard returns the day something drives the agent. `--agent` alongside a workspace `startup` is refused rather than resolved, because picking a winner would silently ignore an instruction and ADR-0007's rule does not stop applying when the instruction arrives on the command line. **The tests are honest about their limit:** five container tests run against a *stub* `claude`, every output shape copied from executed 2.1.220 including the exact negative JSON the Mac produced under I-44 — which tests Yantra's orchestration for real and says nothing about the binary. - **2026-07-31 (cont.)** — **Y-061 done: `yantra logs <name>`.** The task said "tail the transcript JSONL", and measuring one first changed the design: **a real 14 MB transcript is an application journal, not a log** — 6,815 records across 13 `type`s, of which `user` and `assistant` are the only two anyone reads, and most `user` records are tool *results*, which are the agent's input and the bulk of the bytes (**I-46**). A literal tail would have shipped megabytes to show `queue-operation` and `file-history-snapshot`. So selection happens on the far side with `grep`, `-n` counts *turns* rather than records, and what crosses the wire is projected down to who spoke, what they said, and which tools they called. **This is the one M3 task Y-059 does not gate** — `logs` never runs `claude`, it reads a file, so the container and the real Mac can both test it fully. Q12's requirement is now a committed test rather than a note: `a_transcript_that_is_still_being_written_reports_a_moving_mtime` asserts the mtime *moved*, because #70632's failure mode is a transcript that exists and stopped growing, which every existence check calls healthy. Both timestamps are taken from the far side's clock, so what is reported is an age rather than the drift between two machines. **Found I-45 by running it on macOS rather than trusting the container**: `stat -c %Y` is GNU-only and macOS answers `illegal option`, so the `stat -f %m` fallback is load-bearing — and Alpine accepts the GNU spelling, so CI would have stayed green forever while the Mac failed. - **2026-08-03** — **[Y-122](../tracker.md#3-task-board) has a proposal, [ADR-0018](adr/0018-the-tmux-server-carries-the-macos-login-session.md), and it proposes the opposite of what the row expected.** The row's candidate was `yantra-agent` installed as a launchd user agent in `gui/<uid>` with Yantra launching Mac sessions *through* it — which amends ADR-0006's reach and grows the heartbeat agent past *reporter*. **Neither is necessary, because of where a pane's process comes from**: keychain reach is a property of a process's launchd session and is inherited at fork, and [ADR-0011](adr/0011-claude-code-runs-as-a-tui-in-tmux.md)'s `respawn-pane -k` is executed by the **tmux server**, not by the ssh session that sent it.
