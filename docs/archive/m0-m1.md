| Y-047 | Honour `branch` in the workspace schema | ✅ done | claude + biswa | Y-043 | **Closed by removing the field** — [ADR-0010](../adr/0010-drop-branch-from-the-workspace-schema.md). The recorded question (refuse? stash? warn?) turned out to be the wrong one twice over. **The question is *when*, not *what*:** `up` returns `Created` or `Attached`, and switching a branch under an `Attached` session changes the tree beneath whatever runs there — a live agent, in M3 — so a checkout could only ever happen at creation, where the dirty-worktree problem mostly does not arise. **And checkout semantics break what M3 is for:** nothing stops two workspaces naming the same `repo` on the same `machine`, one directory holds one branch, so under `git checkout` two agent workspaces fight. `git worktree` does not. Rather than build semantics M3 would replace, the field is gone and branch selection returns as worktrees when M3 says what it needs. `deny_unknown_fields` makes a stale file fail loudly and name the field, which is the whole migration. ## Session log, M0 and M1

- **2026-07-28 (cont. 5)** — **Y-033: CI landed.** GitHub Actions runs `fmt`, `clippy`, `test`, `deny` and the arm64 `cross` build in parallel on every PR to `main`. Each job invokes a `just` recipe rather than a copy of the command, which is the whole design: the workflow and the local gate are the same list by construction. That forced two justfile changes — `check` now includes `deny` (CI was auditing licences the pre-commit gate did not), and a new `ci` recipe = `check` + `appliance` reproduces a full run locally. The cross job asserts the ELF header is *ARM aarch64, statically linked* before uploading, because a cross-build that silently emits x86_64 passes every other check in the file. Rust version comes from `rust-toolchain.toml` alone; zig is pinned to 0.16.0 in the workflow, the one version that lives in two places.
- **2026-07-28 (cont. 7)** — PR #4 merged (Y-038, Y-039). zig now declared in exactly one place (`.github/actions/setup-zig`); `ci.yml` adopted the `setup-rust` composite, removing five `rustup show` and three cache steps while keeping the no-raw-cargo property. Genuine find: `Swatinem/rust-cache` was pinned to an **annotated tag object SHA** (`23869a5`, tag v2.9.1) in one place and the real commit (`c19371`) in another — verified via the GitHub API and consolidated to the commit. CI badge added.
