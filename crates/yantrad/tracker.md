# yantrad — tracker

The slice of [`tracker.md`](../../tracker.md) that belongs to this crate: **the invariants that bind
code in `crates/yantrad`**, and nothing else. The main tracker still owns milestones, tasks,
decisions, open questions and risks, and it still wins when anything disagrees with it.

**The daemon exists now but is small**: it binds, serves `/healthz`, and refreshes a snapshot in the
background (Y-069, Y-070). Most of the invariants below were earned during research, before there was
anywhere to put them, and **none of those has been exercised by shipped code yet** — the daemon holds
no state on disk and makes no placement decisions. **I-58, I-59, I-60, I-63 and I-64 are the exception**: each was
read off shipped code rather than off research. I-58 and I-59 have never been seen; **I-60 and I-64
have**. Shipped code enforces those two here, and I-63 in
[`yantra-core/src/ssh.rs`](../yantra-core/src/ssh.rs), where every `ssh` argv is built (Y-329).

## Invariants

Non-obvious rules that research proved the hard way. Violating one of these produces a bug that looks
like something else entirely. **[V]** = verified by execution, **[D]** = documented only.

| # | Invariant | Why | Src |
| --- | --- | --- | --- |
| I-7 **[D]** | Own reboot recovery in Yantra's own store. Do **not** adopt tmux-resurrect/continuum. | They re-run whitelisted commands rather than restore processes, on a 15-minute lossy timer — worse than nothing for an agent session. | R2 |
| I-10 **[D]** | **If a signal is not in the decision record, it must not influence the decision.** | The explainability contract. `yantra why` is worthless the moment a hidden term can move the outcome. | R5 |
| I-11 **[D]** | Tie-breaks are deterministic: score → static `priority` → name. Explicitly **reject** kube-scheduler's random tie-break. | Reproducibility is the whole point of an explainable placement. | R5 |
| I-12 **[V]** | **Set `busy_timeout` and `journal_mode = WAL` explicitly on every connection open.** Never rely on the binding's default. | Verified against **two independent SQLite bindings**, both of which default `busy_timeout` to 0 with no constructor option. This is a SQLite-binding trap rather than a property of any one runtime, so confirm it for `rusqlite` too. Five machines heartbeating every 10 s will otherwise produce intermittent `SQLITE_BUSY` that presents as a network or agent fault. | R6 |
| I-13 **[D]** | **SQLite calls go through `spawn_blocking`. Keep queries O(small) regardless.** | `rusqlite` wraps a synchronous C API. Called directly from an async task it stalls the tokio worker serving WebSocket terminal streams. Measured on a synchronous binding elsewhere: one 400 ms query while 100 requests arrived served **0 of 100**. Rust has the proper fix; the trap is the same. | R6 + ADR-0004 |
| I-14 **[D]** | **No ORM in v1** — `rusqlite` with hand-written SQL. Back up with `VACUUM INTO`. | Yantra's schema is four small tables. Diesel/SeaORM buy migrations and compile-time type-safety we do not yet need, at the cost of build time and indirection. Revisit when the schema stops being trivial. | R6 + ADR-0004 |
| I-18 **[V]** | **The PTY must give the child a controlling terminal**, or `^C` will not work. Verify this explicitly in the `portable-pty` integration test.<br>**Verified 2026-08-04 (Y-127), and the rule survives its own reason.** Run against `portable-pty` 0.9 in [`yantra-core/tests/pty.rs`](../yantra-core/tests/pty.rs) with `set_controlling_tty(false)` — `setsid()` and no `TIOCSCTTY`, the shape this was found in — **`^C` still killed the process in the remote pane.** What that PTY lost instead was `SIGWINCH`: `master.resize()` reached nobody and the far side silently kept the size it was opened with. | Found the hard way in a PTY implementation that skipped `setsid()` + `TIOCSCTTY` when the terminal was constructed before the child rather than with it: `^C` never delivers `SIGINT` and `/dev/tty` resolves to the parent's. The bug is language-independent and easy to ship unnoticed — an interactive terminal that cannot be interrupted.<br>**That holds where the PTY's child *is* the interactive program. Here the child is `ssh`, and one hop moves where the interrupt is made:** the `0x03` is a byte `ssh` forwards, and the `SIGINT` is generated by the far side's line discipline. So breaking this ships a terminal that cannot be **resized** — quieter than one that cannot be interrupted, and no less real. | R6, Y-127 |
| I-58 **[D]** | **`listen_on` runs once, at start, so an address that changes under a healthy daemon is never noticed.** The listeners stay bound to something that is gone, and the process has not failed, so `Restart=on-failure` never fires. | A node key regenerated, or a re-auth that moves this machine's tailnet address, leaves `yantrad` serving where nothing routes — and the supervisor is deliberately the only retry mechanism there is ([Y-142](../../tracker.md#3-task-board)), which makes this the one failure it cannot see. **Nobody has seen it and nobody has looked**: it is a 24/7 property, and until M7 there has been no 24/7 deployment for it to show up in. | [the M7 plan](../../docs/plans/m7-appliance.md) §3.1, Y-142 |
| I-59 **[D]** | **A restart is a notification hole.** `notify::Watch` lives in the process, so every restart re-arms *the first look after a start says nothing* and no change that a restart straddles is ever sent. | The rule that stops a reboot mailing a report about every session on the fleet is the same rule that swallows the one crash the reboot happened during, and neither leaves a trace: a notification that was never sent looks exactly like nothing having happened. It is not a bug in the rule — with nothing persisted there is no previous state to diff against — and closing it needs a store, which [Y-044](../../tracker.md#what-closed-and-what-it-steered) dropped after finding no consumer. **A notification record is one of the two things that row names as what would bring one back.** Sharper on the appliance than anywhere else, because `Restart=on-failure` is deliberately the only retry there is ([Y-142](../../tracker.md#3-task-board)) and I-58 is a second way to arrive here. **Nobody has seen it and nobody could have**: the notifier has never run against a relay. | Y-146 |
| I-60 **[V]** | **A check made at startup over something the filesystem owns is not a guarantee at request time, and the request path has to be able to report the thing having gone.** `YANTRA_WEB` is validated once; a directory deleted under a running daemon leaves `ServeDir` **and** its `ServeFile` index fallback both answering an empty 404, which is the deep link's own status. Enforced in [`web.rs`](src/web.rs): a `map_response` layer stats `index.html` on the 404 path and answers **503** naming it, said once at `error` and again at `info` when it comes back. | M6's acceptance run found it — `YANTRA_WEB` pointed into a git worktree that was later removed — and the daemon went on serving, with nothing in the journal and a blank page in the browser: indistinguishable from a dashboard that is simply broken. **It is I-58's shape one layer out**, a condition proved once and then quietly stopping, with nothing failing for a supervisor to see; the difference is that this one is on a request path, so the request is what can say it. The answer is a report and never an exit, because the API, the heartbeat and the terminal socket are all still serving and only the dashboard's files are gone. **The embedded half cannot have it** — its files are a table the compiler built. | Y-155 |
| I-63 **[V]** | **A machine name from a URL reaches `ssh`'s argv with nothing between it and the process.** A name beginning with `-` is read by `ssh` as an option rather than as a destination. Enforced in [`yantra-core/src/ssh.rs`](../yantra-core/src/ssh.rs): `destination_args` puts `--` before the destination in every argv it builds, and `yantra attach` does the same before its own. Proved in [`tests/pty.rs`](../yantra-core/tests/pty.rs): a name of `-V` is refused as a host, where it printed the version and exited 0 before. | Found while building `POST /api/machines/{name}/readiness` ([Y-197](../../tracker.md#3-task-board)), and **it is not new**: `POST /machines/{machine}/probe` shipped the same path first, and [ADR-0009](../../docs/adr/0009-machine-names-are-ssh-destinations.md) makes a machine name an ssh destination on purpose, so the daemon holds no register to check one against. The caller is an owner node the tailnet identified either way ([ADR-0016](../../docs/adr/0016-the-dashboard-writes-and-tailscale-identity-authorises-it.md)), so this escalates nothing — it is a boundary nobody had written down. `--` before the destination, or a leading-dash refusal, is the whole fix. | Y-197, Y-329 |
| I-64 **[V]** | **A nested router with no fallback of its own hands a miss to the *outer* fallback.** The dashboard is that fallback, so any path under `/api` that no route claimed answered **`200 text/html`** with `index.html`. Enforced in [`api.rs`](src/api.rs): the `/api` router carries a fallback of its own, a JSON 404 in the `{"error": …}` shape every other error on this seam uses. | Found on 2026-08-10 restarting a stale daemon: `/api/readiness` on a binary predating that route returned the dashboard, so an absent route and a served page were one answer. **It is [I-60](#invariants)'s shape one route up** — a wrong answer that reads as a right one — and the SPA fallback is what makes it reachable, because a deep link and an API miss are the same request to a router that knows only paths. Both halves are the done condition, so `main.rs` composes the tree in `app`, apart from `serve`, where a test can drive them together. | Y-169 |

One of these carries a warning about its own age. **I-12 was not verified against the crate this
project actually uses** — it was measured on two other SQLite bindings; the trap belongs to SQLite's
C API rather than to any one binding, so it is *expected* to hold for `rusqlite`, but expected is not
measured. **I-18 no longer carries that warning**: Y-127 ran it against `portable-pty` in a
disposable podman container, and the amendment above is what it found. Note what that container can
and cannot say — tmux **3.5a** on Alpine, where both real machines run **3.7b** (I-42), and Linux
only, so nothing here has been seen on macOS.

## Open work

Task rows live in [`tracker.md` §3](../../tracker.md), which is where to look for what is open.

**Y-118, which this section named as open against this crate, closed on 2026-08-05.** `tailscale serve` launders the caller's address, so ADR-0016's
authoriser saw the proxy;
[ADR-0017](../../docs/adr/0017-the-forwarded-address-is-the-caller-when-the-hop-is-ours.md) — the
forwarded address is the caller when the TCP peer is one of this daemon's own bind addresses, and
never otherwise — was accepted by the owner and built in
[`write.rs`](src/write.rs), which `terminal.rs` calls. ADR-0016 stays immutable and carries a second
dated amendment saying so. **Y-020** is closed and its telemetry ADR ([ADR-0013](../../docs/adr/0013-the-heartbeat-carries-only-what-placement-scores.md))
was accepted on the same day.

**Y-044 is closed** — dropped 2026-08-02 without being built. Session state is derived from tmux
(`pane_start_command`, Y-091) and declared in the workspace TOML, and the audit found no consumer for
a store: the snapshot is deliberately in memory, the heartbeat is deliberately not kept, and nothing
asks the daemon to remember. The tracker row records what would bring one back, and it is a placement
or notification record rather than session state.
